$ qits git-credential
Missing required parameter: '<get|store|erase>'
Usage: qits git-credential [-hV] <get|store|erase>
Git's credential helper for the platform's git host. Git runs it; a person does
not.
On a workstation `qits git-login` sets it up: get prints that sign-in's access
token, refreshing it first when needed. store is ignored. erase drops the
cached access token and keeps the sign-in.
With a workspace token (QITS_TOKEN) get answers https://githost.qits.
<QITS_DOMAIN> with that token, and answers no other host; store and erase do
nothing and no file is written.
With QITS_PLATFORM set and no QITS_TOKEN it answers nothing: every action
prints nothing, writes no file and exits 0, so Git asks its other helpers.
      <get|store|erase>   What Git asks for.
  -h, --help              Show this help message and exit.
  -V, --version           Print version information and exit.

Exit codes:
  0   Done. For a host without a sign-in, and with a workspace token for any
        host but the public git host, it prints nothing and Git asks its other
        helpers. A credential that cannot be had says why on stderr and still
        exits 0, so Git carries on.
  1   The sign-in file cannot be read or written.
  2   No action named.

Examples:
  git config --global --get-all credential.https://githost.qits.<QITS_DOMAIN>.
